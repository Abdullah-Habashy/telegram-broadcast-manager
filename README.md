# Telegram Broadcast Manager

لوحة تحكم لإدارة جهات اتصال بوت تليجرام وإرسال رسائل جماعية (Broadcast) — جدولة، قوالب، تصنيفات، وتقارير نجاح/فشل.

## الستاك

- **Backend:** Node.js + Express 5 + Telegraf (بوت تليجرام)
- **قاعدة البيانات:** PostgreSQL
- **الجدولة:** node-cron (يفحص كل دقيقة)
- **الواجهة:** EJS + JS عادي (من غير خطوة build منفصلة)

## التشغيل محليًا (للتجربة)

```bash
npm install
cp .env.example .env
# افتح .env واملأ DATABASE_URL و SESSION_SECRET و ENCRYPTION_KEY

# ولّد قيمة عشوائية لـ SESSION_SECRET و ENCRYPTION_KEY بالأمر ده (شغّله مرتين، واحدة لكل واحد):
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"

npm run migrate   # ينشئ كل الجداول في قاعدة البيانات
npm run dev        # يشغّل السيرفر مع إعادة تشغيل تلقائي عند أي تعديل
```

هيفتح على `http://localhost:3000`. سجّل حساب جديد من `/register`، وبعدين روح **الإعدادات** وسجّل توكن البوت.

> ملحوظة: لو `PUBLIC_URL` مش متحدد، البوت هيتسجل بس مش هيستقبل تحديثات (زي `/start` أو الرسائل)، لأن الـ Webhook محتاج دومين عام بـ HTTPS. للتجربة المحلية ده متوقع.

> ⚠️ **متحطّش رابط عام في `.env` المحلي.** Telegram بيسمح بـ Webhook واحد بس للبوت، فأي تسجيل من الجهاز المحلي **هيسحب البوت من سيرفر الإنتاج** ويوقف استقبال الرسائل على الموقع الفعلي.

## النشر (Deployment)

التطبيق **منشور وشغّال دلوقتي** على VPS برابط ثابت:

```
https://habashy-follow-up.com
```

الدومين مربوط بالسيرفر عن طريق **Cloudflare Named Tunnel**، فمفيش أي منفذ مفتوح على السيرفر، والرابط ثابت مايتغيّرش عند إعادة التشغيل.

الخدمات على السيرفر مُدارة بـ `systemd`:

| الخدمة | الوظيفة |
|---|---|
| `telegram-broadcast-manager` | تطبيق Node (`/root/app`) |
| `cloudflared-tunnel` | التانل اللي يربط الدومين بالسيرفر |
| `postgresql` | قاعدة البيانات |

### تحديث الإنتاج بعد أي تعديل

> ⚠️ **`/root/app` على السيرفر مش git repository.** النشر بيتم برفع الملفات يدويًا من جهاز التطوير (نسخ مباشر)، مش بـ `git pull`. يعني `git` على السيرفر مش موجود أصلاً كخيار حاليًا.

الخطوات الحالية: تُنسخ الملفات المتغيّرة إلى `/root/app` ثم تُعاد الخدمة.

```bash
# من جهاز التطوير — مثال لنسخ ملف أو مجلد
scp -i <path-to-key> -r src/ root@<server-ip>:/root/app/

# على السيرفر — لو فيه تغيير في الـ dependencies أو الـ schema
cd /root/app && npm install --omit=dev && npm run migrate
systemctl restart telegram-broadcast-manager
```

**عيوب الطريقة الحالية** (مسجّلة للمعالجة): مفيش تاريخ إصدارات على السيرفر، ومفيش rollback، ومفيش طريقة مؤكدة تعرف بيها أي نسخة منشورة غير مقارنة checksums. كمان `master` على GitHub **مش** بيمثّل الإنتاج بالضرورة. التحويل لنشر مبني على git هو التحسين المطلوب.

### متابعة الحالة واللوجز

```bash
systemctl status telegram-broadcast-manager
journalctl -u telegram-broadcast-manager -n 100 --no-pager
```

> بيانات الدخول للسيرفر وقاعدة البيانات والدومين موجودة في ملف `ACCOUNTS.md` المحلي — **مستبعد من المستودع عن قصد** (`.gitignore`) ومش مرفوع على GitHub.

> **متوقف:** كان المشروع بيستخدم قبل كده Cloudflare **Quick Tunnel** برابط `trycloudflare.com` مؤقت يتغيّر كل تشغيل. الطريقة دي ألغيت بالكامل بعد الانتقال للسيرفر والرابط الثابت.

## هيكل المشروع

```
src/
  server.js              نقطة البداية
  config/                إعدادات البيئة والاتصال بقاعدة البيانات
  bot/                    منطق بوت تليجرام (botManager + handlers)
  db/                     schema.sql + سكريبت الـ migration
  routes/, controllers/   واجهات الـ API لكل ميزة
  middleware/             حماية الصفحات المحمية بتسجيل الدخول
  jobs/scheduler.js       فحص الرسائل المجدولة كل دقيقة
  utils/crypto.js         تشفير/فك تشفير توكن البوت
  views/                  صفحات EJS (تسجيل دخول، تسجيل، لوحة التحكم)
public/style.css          التنسيق
```
